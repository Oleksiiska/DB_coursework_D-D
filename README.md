# D&D Adventures

Пошук модулів пригод D&D, картки й навігація, рекомендації, статистика
реальної гри та панель моніторингу збору даних у реальному часі. Курсова
робота з баз даних та інформаційних систем: архітектура — розділ 3 звіту
(шарова й гексагональна архітектура, CQRS), реалізація — розділ 4
(поліглотне сховище, джерела даних, інтерфейс, контейнеризація).

| Частина | Що використано |
|---|---|
| Документне сховище | MongoDB 8.0: шардований кластер із трьох шардів, ключ `{ shard_key: 1, _id: 1 }`, зони за `shard_key` (п. 4.3) |
| Пошуковий індекс | Elasticsearch 9: індекси `adventures_idx`, `monsters_idx`, `encounters_idx`, аналізатор `english` (п. 4.6, таблиця 4.12) |
| Графове сховище | Neo4j 5.26: рекомендації, монстри, що трапляються разом, співавтори, ланцюжки кампаній |
| Черга, кеш, лічильники | Redis 7.4: потік Redis Streams із групою споживачів, кеш з часом життя, лічильники й посекундні швидкості (п. 4.7–4.8) |
| Джерела | підготовлені CSV, генератор (×N), краулер каталогу itch.io |
| Інтерфейс | FastAPI + SSE, статична сторінка з Chart.js: вкладки «Моніторинг», «Пошук», «Статистика гри» (п. 4.9) |

## Повна система: шардований кластер

Потрібен Docker Desktop (Windows, macOS) або Docker Engine з плагіном
Compose (Linux) і близько 5 ГБ пам'яті для контейнерів (у Docker Desktop —
Settings → Resources). Команди виконуються в корені проєкту.

1. Покладіть підготовлені CSV (таблиця 2.3, формат — розділ «Формат
   підготовлених CSV» нижче) у каталог `data/csv/` або вкажіть інший
   каталог змінною `CSV_HOST_DIR`.
2. Запустіть усю топологію таблиці 3.7:

   ```
   docker compose -f docker-compose.cluster.yml up --build -d
   ```

3. Відкрийте http://127.0.0.1:8000 — веб-інтерфейс і API.

Compose піднімає сервер конфігурації й шарди, маршрутизатор `mongos`,
виконує одноразовий `mongo-init` (набори реплік, шарди, зони, шардування
`dnd.adventures`), потім сховища, API та процеси. `csv-loader` публікує
ігрові світи зі списку вручну й CSV у чергу і завершується; генератор
працює зі швидкістю, заданою повзунком інтерфейсу (до першої зміни —
100 док/с); краулер обходить каталог itch.io один раз; `ingest-worker`
записує пакети з черги в MongoDB, Elasticsearch і Neo4j.

Скорочення: `DC` = `docker compose -f docker-compose.cluster.yml`.

| Контейнер | Призначення |
|---|---|
| `mongo-config` | сервер конфігурації, набір реплік `cfg` з одного вузла |
| `mongo-shard-1`…`3` | шарди, набори реплік `shard1`…`shard3`, том на шард |
| `mongos` | маршрутизатор; назовні — лише `127.0.0.1:27017` |
| `mongo-init` | одноразово: набори реплік, шарди, зони, шардування за `{ shard_key: 1, _id: 1 }` (`docker/mongo-init.js`) |
| `elasticsearch`, `neo4j`, `redis` | пошуковий індекс, граф, черга й кеш — лише в мережі `backend` |
| `api` | REST API (таблиця 4.15), потік SSE `/api/stats/stream`, сторінка інтерфейсу; `127.0.0.1:8000` |
| `csv-loader` | світи зі списку вручну, потім CSV пакетами по 500 рядків зі швидкістю `CSV_RATE` (1000 рядків/с) |
| `generator` | генератор пригод; масштабується, кожен екземпляр бере частку r = R / N цільової швидкості |
| `crawler` | краулер itch.io: robots.txt, затримка 1,5–3 с, сталий User-Agent |
| `ingest-worker` | процес запису: черга → три сховища → підтвердження пакета; масштабується |
| `storage-check` | перевірка запису й читання через `mongos` (п. 4.2) |

| Що зробити | Команда |
|---|---|
| масштабувати генератор і процес запису | `DC up -d --scale generator=3 --scale ingest-worker=2` |
| запустити без краулера | `DC up -d --scale crawler=0` |
| повторно завантажити CSV (запис ідемпотентний) | `DC up csv-loader` |
| журнал процесу | `DC logs -f ingest-worker` або файли `logs/*.log` |
| налаштування кластера | `DC logs mongo-init` — останній рядок `кластер готовий: шарди shard1, shard2, shard3` |
| шарди й зони | `DC exec mongos mongosh --quiet --eval "sh.status()"` |
| розподіл пригод за шардами | `DC exec mongos mongosh dnd --quiet --eval "db.adventures.getShardDistribution()"` |
| пошукові індекси | `DC exec elasticsearch curl -s "localhost:9200/_cat/indices?v"` |
| глибина черги | `DC exec redis redis-cli xlen queue:documents` |
| пошук через API | `curl "http://127.0.0.1:8000/api/search/adventures?q=cursed+village&level=3"` |
| зупинка | `DC down`; з видаленням даних — `DC down -v` |

Якщо порт 27017 або 8000 на комп'ютері зайнятий, задайте інший:
`MONGOS_PORT=27018 API_PORT=8080 DC up -d`. На Linux, якщо ваш UID не 1000,
запускайте з `APP_UID=$(id -u) APP_GID=$(id -g)`, щоб процеси могли писати
в змонтований каталог `logs/`. Повторний запуск `mongo-init` безпечний:
кожен крок пропускається, якщо вже виконаний, а кластер зі старим ключем
`{ shard_key: 1 }` переводиться на складений командою `refineCollectionShardKey`.

### Журнали

Конфігурацію журналів задає `config/logging.yaml` (п. 4.10); файл
змонтовано в усі контейнери застосунку лише для читання. Записи йдуть у
стандартний вивід (`DC logs`) і в `logs/` з ротацією по 10 МБ:
`api.log`, `csv-loader.log`, `crawler.log`, `storage-check.log`,
`generator-<контейнер>.log`, `ingest-worker-<контейнер>.log`. Браковані
документи й нерозпізнані значення словників — окремо, у
`logs/quality/rejected-<контейнер>.jsonl` і `unknown-terms-<контейнер>.jsonl`.
Детальність без перебудови образу: `LOG_LEVEL=DEBUG DC up -d ingest-worker`
або зміна рівня підсистеми в `config/logging.yaml` (наприклад, `db: {level: DEBUG}` —
тривалість звернень до сховищ і `explain` кожного сотого запиту до шардованої колекції).

### Демонстрація

1. Вкладка «Моніторинг»: пересуньте повзунок зі 100 на 2000 док/с —
   за кілька секунд піднімаються графіки згенерованих і збережених
   документів та приросту в MongoDB; після повернення до 100 вони
   опускаються. Глибина черги показує, чи встигає процес запису; на межі
   50 пакетів джерела призупиняються (зворотний тиск).
2. `DC up -d --scale generator=3` — панель показує 3 екземпляри й частку
   кожного; сумарна швидкість лишається заданою повзунком.
3. Кількості на шардах і відхилення від середнього перевіряють рівномірність
   розподілу за зонами `shard_key`.
4. Вкладка «Пошук»: запит англійською, фільтри, сортування, підсвічені
   фрагменти й кількості за тегами; картка пригоди — автори, монстри,
   схожі пригоди й ланцюжок кампанії; картки монстра, автора, персонажа.
5. Вкладка «Статистика гри»: популярні монстри, типові закляття класу й
   рівня, склад партій, класи й раси, медіани тривалості та раундів бою.

## Перевірка сховища на одному вузлі

```
docker compose up --build storage-check
```

Compose збирає образ застосунку, запускає контейнер `dnd-mongo`, чекає,
доки він відповість, і запускає `dnd-storage-check`. Процес записує
пригоду через порт `CrudRepository`, читає її назад, порівнює й
завершується з кодом 0, якщо документи збіглися. Очікуваний вивід
(час, ключ пригоди, `shard_key` і зона щоразу інші):

```
INFO    launcher: процес storage-check, сховище mongodb://mongo:27017, журнал /app/logs/storage-check.log
INFO    storage-check: запис пригоди db1b9c9a-b49a-4ca1-9d97-71bc85ec628b «The Cursed Village of Mirefen», shard_key 0058 (зона 1 з 3)
INFO    storage-check: прочитано: «The Cursed Village of Mirefen», рівні 1–3, гравців 3–5, теги horror, investigation, відгуків 1
INFO    storage-check: прочитаний документ збігається із записаним: так
INFO    storage-check: пригод у колекції: 1
```

Зона — діапазон `shard_key`, закріплений за шардом: на одному вузлі
документ лежить на ньому, у кластері (`DC up storage-check`) — на шарді
цієї зони. Документи в сховищі: `docker compose exec mongo mongosh dnd --eval "db.adventures.find()"`;
зупинка — `docker compose down` (з даними — `docker compose down -v`).

## Формат підготовлених CSV

Скрипти офлайн-підготовки (розділ 2) до образу не входять. Застосунок
читає їхній результат — файли таблиці 2.3 у каталозі `CSV_DIR`:
`monsters.csv`, `characters.csv`, `encounters.csv`, `participations.csv`,
`authors.csv`, `tags.csv`, `adventures.csv`. Ігрові світи беруться зі
списку вручну `app/data/settings.json`. Відсутній файл пропускається з
попередженням у журналі.

* Назви колонок — назви полів моделі (додаток А звіту). Порожня клітинка —
  відсутнє значення (null), а не порожній рядок.
* Переліки — JSON-масив (`["horror", "one-shot"]`) або рядок через `|`.
* Складені значення — JSON: `statblock` монстра, `classes_all` і
  `combat_payload` персонажа, `reviews` пригоди.
* Об'єкти-значення — окремими колонками: `level_min`, `level_max`,
  `players_min`, `players_max`, `price`, `currency` пригоди; `hp_current`,
  `hp_max`, `hp_status` персонажа й запису участі.
* Час — ISO 8601 або Unix-час.

Якщо ключа документа у файлі немає, процес запису обчислює детермінований
ключ — UUID версії 5 від природного ключа в просторі імен виду документа
`uuid5(NAMESPACE_URL, "https://github.com/Oleksiiska/DB_coursework_D-D/" + <вид у множині>)`
(п. 2.8.3). Повторне завантаження тих самих рядків перезаписує ті самі документи.

| Файл | Ключ | Природний ключ |
|---|---|---|
| `adventures.csv` | `adventure_id` | `itch_id` |
| `monsters.csv` | `monster_id` | `slug` (index SRD) |
| `authors.csv` | `author_id` | `profile_url`, інакше `name` |
| `tags.csv` | `tag_id` | назва `name` після зведення до словника |
| `characters.csv` | `character_id` | `name:controller_hash` |
| `encounters.csv` | `encounter_id` | — (обов'язковий у файлі) |
| `participations.csv` | `encounter_id` + `instance_label` | — |
| `app/data/settings.json` | `setting_id` | `slug` |

запустіть кластер (`DC up -d mongos mongo-init`) і залиште `MONGO_URI`
тим самим — `mongos` відкритий на `127.0.0.1:27017`.

### Навантажувальні сценарії (розділ 6)

`tests/load/locustfile.py` — профілі користувачів за групами запитів:
пошук (групи 1–3, 9) з часткою повторюваних запитів для оцінки кешу,
картки й рекомендації (4–6, 8), статистика гри (7), відкрита панель
моніторингу (потік SSE). API має бути запущене, а сховища — наповнені.

```
locust -f tests/load/locustfile.py --host http://127.0.0.1:8000
locust -f tests/load/locustfile.py --host http://127.0.0.1:8000 --headless -u 100 -r 10 -t 5m --csv logs/load
LOAD_STEPS=10,50,100,200,400 LOAD_STEP_SECONDS=60 locust -f tests/load/locustfile.py --host http://127.0.0.1:8000 --headless --csv logs/load-steps
LOAD_RATES=100,1000,2500,5000 LOAD_RATE_SECONDS=60 locust -f tests/load/locustfile.py --host http://127.0.0.1:8000 --headless -u 50 -r 5 -t 4m --csv logs/load-write
```

Перша команда відкриває веб-інтерфейс Locust на http://localhost:8089.
`LOAD_STEPS` задає ступінчасте навантаження (точка насичення шляху запитів),
`LOAD_RATES` — сходинки цільової швидкості генерації через `POST /api/rate`
(затримки шляху запитів під навантаженням шляху команд), `LOAD_REPEAT_SHARE`
(0,7) — частку повторюваних пошукових запитів, `LOAD_THINK` (`0.5,2`) —
паузу користувача між діями.

## Конфігурація

Процеси налаштовуються лише змінними середовища (той самий образ працює
локально й у Compose); значення за замовчуванням — для запуску поза
контейнерами.

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `MONGO_URI`, `MONGO_DATABASE` | `mongodb://localhost:27017`, `dnd` | документне сховище; у кластері — `mongos` |
| `SEARCH_URL`, `GRAPH_URI` | `http://localhost:9200`, `bolt://localhost:7687` | пошуковий рушій і граф |
| `CACHE_URL`, `QUEUE_URL` | `redis://localhost:6379` | кеш і лічильники; черга |
| `SHARD_COUNT` | `3` | кількість зон `shard_key` |
| `CSV_DIR`, `CSV_RATE` | `./data/csv`, `1000` | каталог підготовлених CSV і швидкість їх читання, рядків/с |
| `DEFAULT_RATE` | `100` | цільова швидкість генератора до першої зміни з інтерфейсу, док/с |
| `QUEUE_LIMIT`, `QUEUE_PAUSE_MS` | `50`, `100` | межа глибини черги в пакетах і пауза джерела перед повторною перевіркою |
| `BATCH_SIZE` | `500` | розмір пакета запису |
| `CRAWLER_BASE_URL`, `CRAWLER_TAG` | `https://itch.io`, `dnd` | каталог і тег обходу |
| `LOG_DIR`, `LOG_CONFIG`, `LOG_LEVEL` | `./logs`, `config/logging.yaml`, порожньо | журнали (п. 4.10) |
| `QUALITY_LOG_DIR` | `./logs` | журнали браку й нерозпізнаних значень |
| `API_HOST`, `API_PORT` | `0.0.0.0`, `8000` | адреса процесу API |

Змінні рівня Compose: `CSV_HOST_DIR` (каталог CSV на комп'ютері),
`MONGOS_PORT`, `API_PORT`, `APP_UID`, `APP_GID`, `LOG_LEVEL`, `CSV_RATE`,
`CRAWLER_TAG`.

Без контейнерів кожен процес запускається з кореня проєкту:
`python -m app.main` (API) і `python -m workers.launcher <csv|generator|crawler|ingest|storage-check>`.

## Розкладка

| Каталог | Шар | Залежить від |
|---|---|---|
| `app/domain` | предметна область: сутності, об'єкти-значення, доменні служби, вихідні порти | нічого, лише стандартна бібліотека |
| `app/application` | сценарії: вхідні порти, команди, запити, DTO | `domain` |
| `app/infrastructure` | адаптери сховищ і джерел, журнали, композиційний корінь | `domain`, `application` |
| `app/presentation` | контролери REST, потік SSE, статична сторінка | `application` |
| `app/main.py`, `workers` | процеси: API, завантажувач CSV, генератор, краулер, процес запису, перевірка сховища | порти `domain` і `application`; адаптери — від композиційного кореня |
| `app/data` | списки вручну: ігрові світи, системи, видавництва, псевдоніми тегів | — |
| `config`, `docker` | конфігурація журналів; ініціалізація шардованого кластера | — |
| `tests` | модульні, інтеграційні, навантажувальні | — |
| `tools` | побудова схем із коду | — |

Вихідні порти (`app/domain/ports/outbound.py`) оголошені в доменному шарі:
без цього неможлива інверсія залежності від сховищ. Вхідні порти
(`app/application/ports.py`) — у шарі сценаріїв, бо їх контракт оперує
об'єктами передачі даних, межовими, а не доменними поняттями.

## Застосовані патерни

| Патерн | Де | Навіщо |
|---|---|---|
| Порти й адаптери | `domain/ports`, `application/ports`, `infrastructure` | заміна сховища чи джерела без дотику до логіки |
| Узагальнений CRUD-репозиторій | `CrudRepository[T]`, `MongoCrudRepository[T]` | автори, теги, світи, записи участі — без окремих класів |
