# Скелет застосунку

Класи-заглушки за архітектурою розділу 3: шари, порти й адаптери, CQRS.
Тіла методів оголошені як `NotImplementedError` — фіксується структура
та контракти, а не поведінка.

## Перевірка

```
python -m pytest tests/unit -q
```

Проходить без піднятих сховищ: сценарії використання залежать лише від
інтерфейсів, а в тестах вони підмінюються заглушками з `tests/unit/fakes.py`.

П'ять тестів стежать за архітектурою автоматично:

| Тест | Що гарантує |
|---|---|
| `test_architecture.py` | правило залежностей: імпорт із зовнішнього шару у внутрішній ламає збірку; домен використовує лише стандартну бібліотеку |
| `test_requirements_coverage.py` | кожна з десяти груп запитів таблиці 1.2 обслуговується вхідним портом, кожен порт має обробник |
| `test_ports_contract.py` | кожен адаптер структурно задовольняє свій порт, без успадкування |
| `test_diagrams.py` | кожен вихідний порт має адаптер, кожен вхідний — рівно один обробник; схеми будуються з поточного коду |
| `test_async_contract.py` | кожен метод порту — співпрограма, і жодна реалізація не підміняє його синхронним |

## Схеми

```
python tools/arch_diagrams.py --out docs/diagrams --plantuml plantuml.jar
```

Будує схеми модулів і класів безпосередньо з вихідного коду й ставить
на них дату. Для фінальної редакції звіту достатньо запустити повторно.

| Каталог | Вміст | Рисунки розділу 3 |
|---|---|---|
| `docs/conceptual` | концептуальні схеми, `arch.puml` — шари, порти й адаптери, CQRS, процеси, послідовності | 3.1–3.4, 3.11, 3.12 |
| `docs/diagrams` | схеми, згенеровані з коду: модулі, доменна модель, реалізації портів, шлях запитів, шлях команд, зріз пошуку; `summary.json` — кількісна зведенка | 3.5–3.10 |

Стан на 28.09.2026: 52 модулі, 130 класів, 10 вхідних і 13 вихідних
портів, 28 зв'язків реалізації.

## Розкладка

| Каталог | Шар | Залежить від |
|---|---|---|
| `app/domain` | предметна область | нічого, лише стандартна бібліотека |
| `app/application` | сценарії | `domain` |
| `app/infrastructure` | адаптери | `domain`, `application` |
| `app/presentation` | подання | `domain`, `application` |
| `workers` | окремі процеси | порти `domain` і `application` |

## Розміщення портів

Вихідні порти (`app/domain/ports/outbound.py`) оголошені в доменному
шарі: без цього неможлива інверсія залежності від сховищ.

Вхідні порти (`app/application/ports.py`) оголошені в шарі сценаріїв,
бо їх контракт оперує об'єктами передачі даних — межовими, а не
доменними поняттями.

## Застосовані патерни

| Патерн | Де | Навіщо |
|---|---|---|
| Порти й адаптери | `domain/ports`, `application/ports`, `infrastructure` | заміна сховища чи джерела без дотику до логіки |
| Узагальнений CRUD-репозиторій | `CrudRepository[T]`, `MongoCrudRepository[T]` | автори, теги, світи, записи участі — без окремих класів |
| Реєстр | `IngestDocumentHandler` | сховище й індекс обираються за видом документа |
| Шаблонний метод | `CachedSearchHandler` | порядок кроків пошуку задано один раз для трьох видів пошуку |
| Розділення інтерфейсів | `EventPublisher` / `EventConsumer` | джерела бачать лише публікацію, процес запису — лише читання |
| CQRS | `application/commands`, `application/queries` | різні моделі для запису й читання |
| DTO | `application/dto` | картка не тягне повний текст пригоди |
| Специфікація | `AdventureFilters`, `MonsterFilters`, `EncounterFilters` | обмеження видачі як незмінні об'єкти-значення |
| Доменна служба | `domain/services` | правила, що не належать жодній сутності |
| Відображення | `DocumentMapper`, `DataclassDocumentMapper` | перетворення документа на сутність окремо від репозиторію |
| Композиційний корінь | `infrastructure/config/container.py` | єдине місце, що знає конкретні реалізації |
| Об'єкт-значення | `LevelRange`, `Money`, `ShardKey`, `SearchHits` | інваріанти на рівні типу |
| Асоціативний клас | `MonsterParticipation` | дані на ребрі «зустріч — монстр» |
| Стратегія | `ThemeProfile`, `PolitenessPolicy` | поведінка, що змінюється без зміни коду |
| Заглушка-подвійник | `tests/unit/fakes.py` | тести без інфраструктури |
